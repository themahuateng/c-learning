## 二、问题清单

### 🔴 1. 除零：先算后判断（顺序反了）

现在的写法：

```c
result = a / b;          /* 先算 */
if (b == 0) { ... }      /* 后判断 */
```

**实测**（我跑了验证程序）：

```
先算 a/b 再判断 b==0 : result = inf
```

double 除法遇到 0 不会崩，得到 `inf`（无穷大），所以现在是"碰巧对"。
**但如果哪天换成整数除法，这里会直接崩溃。**

正确顺序：**先判断 `b == 0`，再算除法。**

### 🟡 2. 输出格式

- `printf("%lf", result)` 打出来是 `7.000000`
- 建议改成 `%.2f` → `7.00`
- 结果后面没有 `\n`，现在靠下一行菜单开头的 `\n` 兜着；菜单格式一改，结果就会和下一行粘在一起

### 🟡 3. 读两个数写了两遍

```c
scanf("%lf", &a);
scanf("%lf", &b);
```

可以合成一句：`scanf("%lf %lf", &a, &b);`

### 🟡 4. 重复代码

"提示输入两个数 + 读入 a、b" 在 4 个分支里重复了 4 次。
可以提到分支外面只写一次（选 0 退出时不读）。

### 🟢 5. 残留的占位注释

- `/* code */` 出现了 6 次，是骨架留下的，全删
- 文件末尾"第 5~7 步"那段注释任务已经完成，删掉（留着会误导）

### 🟢 6. 缩进不齐

`}   else if (choice == 3)`、结尾的 `return 0;` 和 `}` 缩进不一致。
VS Code 里全选 → `Shift + Alt + F` 一键格式化。

### 🟢 7. 中英混搭

菜单是英文、提示是中文。选一种统一（小事，但专业感从这里来）。

## 三、🔵 进阶挑战

**输入校验**：现在如果用户输入字母会怎样？

实测（我跑了验证程序，输入 `abc`）：

```
scanf 返回值 = 0
choice 现在的值 = 99      ← 保持旧值不变
```

在你的计算器里，这意味着 `choice` 还是上一次的值，菜单会**无限循环打印**。

解法方向：检查 `scanf` 的返回值（返回 1 才是成功），失败时清掉输入缓冲再让用户重来。
