# 算法题库（训练用，不是题号列表）

> 建立日期：2026-10-30  
> 目的：把“知道某道题”升级成“知道为什么现在做、做完要证明什么、错了怎么补、以后怎样复查”。  
> 真相源：本目录是算法训练的题库入口；`LEARNING_STATE.md` 只记录当前进度。

## 一、先把四个问题说清楚

### 1. 能把题搜罗完吗？

**不能承诺“搜罗完所有题”。** 算法题没有唯一全集，平台会更新，且同一道题的题面也会变化。  
能做的是建立一套可审计的覆盖体系：

- 课件例题全量登记；
- 每个算法主题至少有一个权威题源；
- 每道进入训练的题都核验题面、输入输出、约束和链接；
- 用“覆盖矩阵”检查有没有整类能力被漏掉；
- 未核验的题明确标成“候选”，不假装已经知道。

### 2. 我“都知道”这些题吗？

**不能这样承诺。** 我不能靠记忆声称知道所有题，也不能用“我记得有这题”代替核验。  
题库里只允许三种事实：

1. **已核验**：打开原题，确认题面和约束；
2. **已训练**：学习者实际做过，且有代码/手算/测试证据；
3. **已掌握**：能独立写、解释、改进并通过变式。

没有证据的内容只能叫“候选”。

### 3. 知道什么时候让学习者做什么题吗？

知道，但不按日历硬塞。选题由四个条件决定：

```text
先修知识达到要求
    + 当前主题已经讲过一个最小例子
    + 当前题只引入一个新难点
    + 上一题的错因已经修正
```

具体顺序写在 `核心题群-数组与基础算法.md`，当前进度只写在 `LEARNING_STATE.md`。

### 4. 会不会漏掉重要题？

**不能保证绝对不漏。** 可以保证：

- 课件例题不漏登记；
- 每个主题必须有“基础题、变式题、综合题、反例/边界题”；
- 重要题不是按热度选，而是按能力覆盖选；
- 发现漏项时，补进覆盖矩阵，不靠事后记忆补锅。

## 二、旧题单的问题

旧版只是“题目索引”，深度不够，缺了这些层：

- 原题约束；
- 先修判断；
- 为什么要做；
- 必须自己手算的样例；
- 反例和常见错误；
- 代码通过之后的追问；
- 变式和迁移；
- 错因记录与复习日期。

所以它不能叫完整题库，只能叫候选目录。

## 三、题库的四层结构

### 第一层：题源层

记录题目从哪里来，避免把 AI 自编题当成权威题。

优先级：

1. 学校课件/C 教材例题；
2. LeetCode/Luogu 官方题单中的题；
3. 经典教材习题；
4. AI 变式题，只用于补练，不替代原题。

### 当前题库不是什么

当前题库**不是蓝桥杯题库，也不是 ACM/ICPC 题库**。

当前目标是：

```text
学校 C 课程例题
    + 基础算法能力（数组、排序、二分、双指针、递归）
    + 可核验的题目契约和题卡
```

不同题源对应的目标不同：

| 题源 | 主要用途 | 现在是否使用 |
|---|---|---|
| C3/C4 课件例题 | 学校课程、教材考试 | 使用中 |
| LeetCode 中文站基础题 | 学算法模式、边界、复杂度 | 使用中 |
| 洛谷官方题单 | C 语法巩固、入门算法、中文题面 | 候选，待核验 |
| PTA / 牛客 | 课程作业、基础编程 | 候选，待核验 |
| 蓝桥杯真题 | 蓝桥杯专项训练 | 暂不使用 |
| Codeforces / ACM 题 | 竞赛速度、证明和综合算法 | 后期再说 |

蓝桥杯和 ACM 不是同一条训练线：

- **蓝桥杯**：可以在基础算法稳定后做专项题单，但仍要补搜索、动态规划、图论、数学和真题。
- **ACM/ICPC**：需要完整的数据结构、图论、DP、数学、复杂度证明和团队训练，不适合现在直接混进 C 语法课。

所以当前先把“课程例题 + 基础算法题群”做实，等基础数据结构过关后，再决定是否开蓝桥杯线或竞赛线。

### 第二层：题卡层

每道进入训练的题必须有题卡，模板见 `题卡模板.md`。

至少要有：

- 输入、输出、约束；
- 先修知识；
- 正常例、边界例、反例；
- 暴力思路和优化目标；
- 不变量；
- 复杂度；
- 常见错误；
- 变式与迁移；
- 验收问题。

### 第三层：训练层

不是“看懂题解”，而是按固定闭环训练：

```text
读题 → 手算 → 设计 → 编码 → 证明 → 测试 → 变式 → 复盘
```

### 第四层：证据层

每次训练至少留下：

- 代码或伪代码；
- 手算表；
- 测试输入和输出；
- 错因；
- 复杂度和不变量说明；
- 下一次复习日期。

## 四、题目什么时候出现

### 不出现

- 先修知识点还没到 `[2]`；
- 题目需要两个以上未学概念；
- 学习者还不能复述上一题的核心不变量；
- 代码虽然跑通，但边界测试还没做。

### 出现

- 当前主题已经有一个最小例子；
- 题目只增加一个新难点；
- 可以先手算出结果；
- 能在 30~60 分钟内完成第一版；
- 做完能迁移到一个相近问题。

## 五、一次题群的深度标准

一个题群至少要经过六层，不是只交一份代码：

| 层 | 证据 |
|---|---|
| D0 认题 | 用自己的话复述输入、输出、约束 |
| D1 手算 | 正常例、边界例、反例各一组 |
| D2 设计 | 先写暴力，再写优化思路 |
| D3 编码 | 先伪代码，再 C 代码 |
| D4 证明 | 说清不变量、为什么停、为什么正确 |
| D5 迁移 | 改条件/改数据结构/改输入，再做一题 |

代码通过只完成 D3。D4 和 D5 没有证据，不能标记“掌握”。

## 六、当前覆盖范围

当前只开 **算法基础线**：

- 数组遍历、最值、反转；
- 原地删除、压缩；
- 双指针；
- 排序（选择、冒泡、插入）；
- 二分查找及变形；
- 递归入门；
- 二维数组。

暂不进入：

- 链表、栈、队列、哈希、树、图；
- 动态规划、最短路、并查集；
- 竞赛难度题。

这些要等 C 主线到对应先修点后再开，避免“同时学十个主题”。

## 七、课程题和算法题的关系

| 类型 | 负责人 | 目的 |
|---|---|---|
| C 课件例题 | C 主线 | 语法、程序结构、教材考试 |
| 算法题群 | 算法基础线 | 建模、不变量、复杂度、迁移 |
| 项目题 | C 主线 | 综合交付、文件、多文件、调试 |

同一道题可以两边都出现，但不重复计算掌握度。

## 八、题目状态

只允许这五个状态：

```text
候选 → 待核验 → 已核验 → 已训练 → 已掌握
```

状态含义：

- **候选**：只是备选，题面和约束未确认；
- **待核验**：准备使用，正在核对；
- **已核验**：题面、输入输出、约束、链接已经确认；
- **已训练**：已经做过，有代码和测试记录；
- **已掌握**：独立复现、证明、变式均通过。
