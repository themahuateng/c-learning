# 测试与验收模板

> 用途：把“代码能跑”升级为“能证明、能测试、能迁移”。

## 一、编译检查

每次至少做：

```text
gcc -std=c17 -Wall -Wextra -g 文件名.c -o 文件名.exe
```

要求：

- 没有错误；
- 警告要能解释，不能直接忽略；
- 多文件项目要明确列出所有 `.c`；
- 涉及内存的题优先再用调试器或内存检查工具复核。

## 二、测试矩阵

每组代码至少考虑下面这些类别，不适用的写明“不适用”：

| 类别 | 例子 |
|---|---|
| 正常输入 | 普通规模、普通值 |
| 空输入/空数组 | `n=0`，空字符串 |
| 单元素 | `n=1` |
| 全相同 | `[4,4,4]` |
| 已有序 | 升序/降序输入 |
| 逆序 | 完全反着来 |
| 重复值 | 排序稳定性、删除重复项 |
| 负数/零 | 最值和统计 |
| 边界值 | 最大/最小允许值 |
| 非法输入 | 非数字、文件不存在 |
| 内存失败 | `malloc` 返回 `NULL` |
| 溢出风险 | `mid * mid`、整数和 |

## 三、每次训练必须留下的证据

```text
题目：
输入：
期望输出：
实际输出：
是否通过：
编译警告：
时间复杂度：
空间复杂度：
核心不变量：
错因：
下次复现日期：
```

## 四、调试阶梯

1. **看错误信息**：是预处理、编译、链接还是运行？
2. **看第一处错误**：后面的错误常常是第一处引起的。
3. **缩小输入**：从 5 个数缩到 1 个数、1 行、1 个字符。
4. **打印中间状态**：数组、下标、指针、返回值。
5. **检查边界**：`0`、`n-1`、`n`、`NULL`、`'\0'`。
6. **检查未定义行为**：越界、未初始化、重复释放、有符号溢出。
7. **最后才看答案**：看完答案要关掉重写。

## 五、掌握判定

只有同时满足以下条件，才可标“已掌握”：

- 不看资料写出第一版；
- 通过正常、边界、反例测试；
- 能解释核心不变量；
- 能说清复杂度；
- 能改一个条件做出变式；
- 隔天还能复现。

否则最多标记“已训练”。
