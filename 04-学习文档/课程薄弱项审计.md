## 二、仍未解决的薄弱项

### P0：必须先补

1. **动态内存正式回验**  
   已有动态数组和动态学生程序经验，但还需要一次不看资料的验收：`malloc → 使用 → free → p=NULL`，并能解释地址和生命周期。

2. **结构体系统回验**  
   已讲 struct、typedef、enum、union、嵌套结构体，但还没有一个完整的“结构体数组 + 排序 + 统计 + 函数传参”独立练习。

3. **S01 选择排序的 D4/D5**  
   已能写升序/降序和手算，但证明、稳定性反例、边界测试还需要一次正式复验。

4. **编译警告与调试**  
   必须从“能编译”升级到“能读懂警告、能定位逻辑错误、能用最小输入复现”。

### P1：近期补

1. 把 C 课件中仍为“待补/待回验”的例题按先修关系排队，不按页数平均推进。
2. 给每个算法题群补一个本地 C 输入输出版本，避免只会在 LeetCode 的函数框架里写。
3. 把 `[2]` 的项目逐步升级到 `[3]`：不是再看一遍，而是关掉资料重写。
4. 每完成一个题群，记录一次“隔天复现”；当天会写不等于掌握。

## 三、近期补课顺序

```text
S02 三种排序对比
    ↓
C 动态内存正式回验
    ↓
结构体数组综合练习
    ↓
S03 二分查找
    ↓
C 指针/字符串专项
    ↓
链表（C 第 14 课）
```

这个顺序的原则是：**先用算法题训练思维，但不能绕过 C 的内存和结构体地基。**

## 四、验收硬标准

每个知识点至少要有：

1. 一份手算或纸上推演；
2. 一份不看资料写出的代码；
3. 一组正常输入；
4. 一组边界输入；
5. 一组反例或错误输入；
6. 一次编译警告检查；
7. 一次错因复盘。

缺任何一项，状态最高只能是“已训练”，不能写成“已掌握”。
